# trading_chart 使用指南

## 何时调用

用户问某个**加密**资产的行情或技术面时调用 `trading_chart`：

- 走势、结构、支撑阻力、能不能买、现在什么位置；
- K 线、均线、MACD/RSI/布林带/KDJ/ATR 等指标；
- 要求"画一张图 / 看一眼行情"。

非加密市场（美股、A 股、外汇、期货）、下单与仓位、回测、纯指标概念问答都不调用本工具。

## 参数

只填能从用户话里解析出来的字段，其余留空，由默认值补齐。

| 参数 | 含义 | 填法 |
|---|---|---|
| `symbol` | 币种或交易对 | `"BTC"`、`"ETH"`、`"BTCUSDT"` 都行；现货对会自动补/剥离成各场所需要的写法（Binance 要 `BTCUSDT`，Hyperliquid 要 `BTC`） |
| `timeframe` | 周期或时间词 | `"15m"`/`"1h"`/`"4h"`/`"1d"`，或下表时间词 |
| `ma` | 均线周期数组 | `[50, 200]`，覆盖默认的 `[20, 50, 200]` |
| `rsi` | RSI 周期 | `14`；传值才显示 RSI |
| `bollinger` | 叠加布林带 | `true` |
| `kdj` | KDJ 副图 | `true` |
| `atr` | ATR 副图 | `true` |
| `compareTo` | 要与当前周期比较方向的另一周期 | `"1w"`（日线对周线）、`"1h"`（15m 对 1h）；不传则不比较 |
| `levelsPerSide` | 图上每侧画几条支撑/阻力 | `5`；默认 3，上限 10 |
| `levelKinds` | 图上画哪几类价位 | `["support","resistance"]`（默认）、`["resistance","fib"]` |
| `levels` | **点名要画哪几条线** | `["85237.96:support","84843:invalidation"]`；类别含 `invalidation`（失效位）；与 `levelsPerSide`/`levelKinds` 互斥 |

## 时间词 → 主周期

- 今天 → 1h
- 这周 → 4h
- 这月 → 1d
- 短线 → 15m

用户话里写出的具体周期优先于时间词；都解析不出来时用默认周期。

## 默认值

- symbol：BTC
- 周期：默认 1h
- 指标：主图 MA20/50/200，副图 成交量 与 MACD；RSI 默认关闭，布林带/KDJ/ATR 默认关闭。

## 多轮对话

同一对话里沿用上一轮的 symbol 与指标设置。用户只改周期或指标时，只传变化的字段。

## 回答要求

**结论前置。** 回答的第一句声明本次使用的 symbol、周期与指标（例如"BTC / 1h / MA20/50/200 + 成交量 + MACD"），猜错时用户能立刻纠正；**紧接着就给结论三件套：方向 + 失效位 + 置信度**。读者应该在前三行拿到答案，而不是翻到最后一段。图表由工具自动打开在**右侧栏的「行情图」tab**里（不在对话正文中）。

### 随后只写判断与依据（三层，但不许灌数据）

判读仍按 `规则信号（机械） → 结构/形态判断（模型） → 综合结论` 组织，用来支撑前面那句话：

| 层 | 写什么 | 要求 |
|---|---|---|
| 规则信号 | 工具返回的规则信号与市场状态中**与结论相关的那几条** | 通常 3–6 个关键数值即可，带时间与价位。**不是把工具返回的指标全列一遍**；其余数值留在工具结果里，用户追问再给 |
| 结构/形态判断 | 你从枢轴与 K 线读出的结构（HH/HL/LH/LL、均线排列、趋势线/通道）与具名形态（头肩、双顶双底、三角、旗形） | 每个判断指出**依据的价格与时间**（如"13:00 高点 63,800 之后的低点依次抬高"）；依据不足就写"不足以判定"，不要硬套形态，也不要为凑层次而写 |
| 综合结论 | 方向 + 失效位 + 置信度（ADR-0002） | 与开头那句一致；说明它建立在上面哪一条证据上 |

优先级：结构与支撑阻力/斐波那契在前，经典形态次之；艾略特波浪最后，只在用户明确要求时展开。

**长度预算**：默认 **≤400 字**（关键数值与那一行结论不算；**Jev 校准的四项数字也不受此限**，见下节）。数字是证据，不是装饰——同一个数值**不要在正文里讲一遍又在表格里抄一遍**。

**图上有什么**：K 线 + 均线 + 离现价最近的支撑/阻力（默认每侧 3 条）。指标**不默认画**，需要时用图卡工具栏的开关打开。价位数量与类别可用 `levelsPerSide` / `levelKinds` 调整（例如 `levelKinds:["resistance","fib"]` 让图上出现斐波那契位）。

**把结论里的价位补画到图上**：分析完（`trading_levels` 已经给出完整价位清单）之后，如果认定某几条值得让用户直接看到——尤其是**失效位**——就在**同一回合**再调一次 `trading_chart`，用 `levels:["85237.96:support","84843:invalidation"]` 点名画上。同一回合的 tab 会被更新（不会多开一张图）；跨回合再画就是新的一张图，旧图按设计保留原样。`invalidation` 类别会用琥珀色与机械的支撑/阻力区分——它是判读，不是算出来的候选，别让用户误读。
以下都**不上图**，但都在你手上的机械数据里，需要时由你在回答里写清楚，不要说"图上已经标了"：斐波那契回撤（线太密）、swing 枢轴点、规则信号箭头（一张 1h 图能到十几个，会压住价格）。

**判断只用已收盘 K 线**：工具返回的一切机械数据都已经剔除了形成中（未收盘）的那根，你也必须照此处理——形成中的 K 线只能用来描述"当前价格在哪"，**不能**用它触发信号、确认突破、认定形态或下结论。图上那根会以半透明弱化色画出来、且不带指标数值；用户问起时照此解释。

### 不给交易建议

本工具只做技术面判读，**不提供交易建议**：

- **不给**：入场价/出场价、止损止盈价位、目标价、仓位或资金比例、杠杆、买卖指令（"建议买入/加仓/清仓"）、收益承诺或胜率保证；
- **给**：方向、失效位、置信度、结构/形态与关键价位——这些是**可证伪的判读**，不是操作指令；
- 失效位说的是"这个判读在什么情况下不成立"，按这个框架表述，不要写成"止损设在 X"。

用户直接问"能不能买 / 该不该卖 / 买多少"时：不给出操作结论，说明本工具只做技术面判读、不构成投资建议，然后照常给出上面三层的判读，把决定留给用户。

方向性结论必须带**方向 + 失效位 + 置信度**。置信度优先用 `trading_confidence` 的校准结果（0..1 与 高/中/低），拿不到时用你自己的判断并**声明未经校准**；不要编造校准分数。分析结论由你根据工具返回的指标数值撰写。

### 表格：只在被要求时给

默认**不附表格**（结论前置 + 判断与依据已经够了）。用户明确要"详细报告 / 汇总 / 列成表"时，才在结尾附一个 Markdown 表格，作为**唯一的数值台账**（层级 / 事实 / 依据的数值与时间）——此时正文不再重复同一批数字。

## 机械数据怎么用

工具给出的机械数据是**确定性计算，不是结论**：

- 锚点里的 `context` 是市场状态（趋势强度与方向、波动率、量能），用作判断的框架；
- 支撑阻力、斐波那契、枢轴与指标值经 `trading_levels` / `trading_indicator` 按需获取；
- 它们全部只用**已收盘 K 线**算出；你的工作是筛选、命名结构与形态，并给出方向 + 失效位 + 置信度。

## 按需取数：什么时候取什么（trading_indicator / trading_levels）

`trading_chart` 只给你**定位与市场状态**（symbol、周期、根数、最新收盘价、最后一根已收盘 bar、趋势/波动/量能）。指标值、支撑阻力、斐波那契、枢轴都要你**按分析路径自己取**——这是刻意的：判读的起点由你决定，不由宿主预设。

### 调用顺序

1. `trading_chart`——出图 + 锚点（先有 symbol 与周期，后面的请求都建立在它上面）。需要多周期共振时**在同一调用里传 `compareTo`** 指定要对比的周期；
2. `trading_indicator`——要指标值。可指定周期与参数，**可以再发一轮**接着看别的；
3. `trading_levels`——要支撑/阻力/斐波那契/枢轴，容差与条数由你定；
4. `trading_derivatives`——要永续合约的衍生品数据（资金费/OI/标记价/预言机价/溢价/冲击价），见下节；
5. `trading_confidence`——形成方向性结论后校准置信度；
6. 写回答，引用工具给出的具体数值与时间。

### 指标请求怎么写

`indicators` 用紧凑字符串，**必须用下面清单里的 id，拼错会调用失败**：

| 类别 | id | 参数 | 用法与坑点 |
|---|---|---|---|
| 均线 | `ma:50` | 周期 | 中/长期趋势基准，兼作动态支撑阻力。滞后，需与更快指标配合 |
| 均线 | `ema:20` | 周期 | 短周期、更灵敏。震荡市噪音大，用长均线过滤 |
| 动能 | `rsi:14` | 周期 | 超买超卖与背离。强趋势里可长期钝化在极值区 |
| 动能 | `macd` / `macd:12/26/9` | 快/慢/信号 | 交叉与背离。低波动区间要交叉验证 |
| 动能 | `mfi:14` | 周期 | 带量的 RSI。成交量尖峰会扭曲它 |
| 波动 | `bollinger:20/2` / `bollingerUpper` / `bollingerLower` | 周期/倍数 | 中轨=20SMA，上下轨 ±2σ。强趋势里价格会贴着轨道走 |
| 波动 | `atr:14` | 周期 | 波动幅度，用来衡量"多少算大波动"。反应滞后，是背景不是信号 |
| 波动 | `supertrend:10/3` | 周期/倍数 | 跟踪止损式趋势线，换向即趋势可能反转。震荡市频繁换向 |
| 趋势强度 | `adx:14` | 周期 | 趋势强度（配 `context.trend` 看方向）。只讲强弱，不讲方向 |
| 量能 | `vwma:20` | 周期 | 量加权均线，比 MA 更能反映真实成交重心 |
| 量能 | `obv` | 无 | 累积量能，看资金是进是出。绝对值的意义小于斜率 |

**每轮建议不超过 8 项**，且互相互补（例如不要同时要 `rsi:14` 和 `mfi:14` 当两个独立证据）。这是**单轮上限**，不是探索的天花板——需要更多就再发一轮。

参数请用清单里的常用档位（`ma:50`/`ma:200`、`rsi:14`、`bollinger:20/2` 等）；用清单外的参数（如 `ma:7`）要在回答里**说明理由**。

### 价位请求怎么写

`trading_levels` 的 `kinds` 可选 `support` / `resistance` / `fib` / `pivots`；`tolerancePct`（默认 1）越小簇越细，`maxLevels` 按触碰次数降序截断。需要"最硬的几条"就调小 `maxLevels`，需要"完整的簇结构"就别传它。每条价位带 `touches`（触碰次数，越多越硬）、`distancePct`（距现价）与 `pivotTimes`（形成它的枢轴时间）。

### 衍生品数据（trading_derivatives，来源 Hyperliquid）

判断"多头是否拥挤"要看资金费与 OI，这些只有永续合约有：

| 字段 | 含义与用法 |
|---|---|
| `funding` / `premium` | 当前资金费率与其溢价分量。**HL 按小时结算**（Binance 多为 8 小时），所以同一资产在 HL 上的样本密度更高 |
| `openInterest` | 未平仓量。配合价格看"增仓上涨/减仓上涨" |
| `markPrice` / `oraclePrice` / `midPrice` | 标记价 / 预言机价（验证者发布的 CEX 加权中位数）/ 中间价。**三者背离本身就是信号** |
| `impactPrices` | 吃下 2 万美元后的实际均价（双边），比中间价更接近真实成交 |
| `volume24h` / `prevDayPrice` | 24h 名义与基础成交量、昨日价 |

两项 **Hyperliquid 独有、Binance 原理上给不了**（只有点名才会去取）：

| 字段 | 为什么独有 |
|---|---|
| `predictedFunding` | 同一个币在 **BinPerp / BybitPerp / HlPerp** 等场所的预测资金费并排给出。某场所显著更高 = 该场所多头更拥挤，这是纯 Binance 数据源拿不到的视角 |
| `openInterestCap` | **OI 已达上限、无法再开新仓**的资产清单——罕见的容量信号，成本极低 |

注意：HL 每个市场只保留**最近 5000 根 K 线**（1h 约 208 天）。工具返回 `truncated` 与 `note` 时，说明这段历史超出保留范围，**长回看要用 Binance**，不要说"当时没有行情"。

### 多周期共振：周期对由你定

高周期定结构与方向、当前周期定时机——但**该拿哪个周期比，取决于问题**：

- 看日线走势 → `trading_chart({ symbol, timeframe: "1d", compareTo: "1w" })`；
- 看 15m 入场 → `compareTo: "1h"`；
- 想确认中期结构 → 甚至可以跨两级，例如 15m 对 4h。

返回 `current` / `higher` 两侧的机械状态（趋势状态、方向、ADX）、`aligned`（是否同向）与 `summary`。**同向是共振，反向是背离**；任一侧走平则"方向不明确"，此时不要把共振当作证据。周期对不写死——你按问题选，选完在回答里说明用了哪两个周期。

**不存在更高周期时不做共振**：`1w` 之上没有更大周期，工具会明确告诉你"不存在比 1w 更高的周期"（不会拿 1w 跟自己比出一个假的"共振向上"）。此时要么指定一个更小的 `compareTo`，要么就不谈共振。

### 用 lookback 直接说"要看多长时间"

`trading_indicator` 与 `trading_levels` 都有可选的 **`lookback`**：语义是**时间**，不是根数。

| 写法 | 含义 |
|---|---|
| `"90d"` / `"2w"` / `"3M"` / `"1y"` / `"36h"` / `"90m"` | 天 / 周 / 月 / 年 / 小时 / 分钟（`M` 或 `mo` 是月，`m` 是分钟） |
| `"500"` | 直接给根数 |

窗口 = **max(指标预热需求, lookback 换算的根数)**，所以：

- 想让分析覆盖三个月，就传 `lookback: "3M"`，**不必**为了撑开窗口去要一条超长的均线；
- 只关心指标本身就不传它（窗口由指标决定）；
- `trading_levels` 的 `lookback` 决定"用哪一段价格结构来定价位"（例如只看最近 60 天的结构）。

写错（例如 `"1x"`）会明确报错并列出可用写法，不会静默回退。

### 取数上限（选周期前先知道）

**按时间思考，不要按根数思考。** 单次请求能覆盖的历史长度取决于你选的周期：

| 周期 | 单次能覆盖 |
|---|---|
| 15m | 约 10 天 |
| 1h | 约 42 天 |
| 4h | 约 167 天 |
| 1d | 约 1000 天（≈2.7 年） |
| 1w | 约 7000 天 |

所以：**先确定要覆盖多长时间，再选周期**。要近两个月的日内走势 → 1h 的 42 天足够；要两年的长期结构 → 用 1d，不要试图在 1h 上要 `ma:500`（那需要 500 根以上的 1h，虽然根数够，但语义上你其实想要的是"长期"，该换周期）。

（根数上限是 1000 根已收盘 K 线/周期；需要更长的历史一律换更大的周期。）

数据源差异：Binance 现货没有保留上限（可分页，但单次仍受上面 1000 根限制）；Hyperliquid 只保留**最近 5000 根**且没有回填，更早的历史必须用 Binance——工具返回 `truncated` / `note` 时说的就是这件事。

### 数据不足怎么办

任一工具返回 `ok=false` 时说明缺多少根（`required` / `available`）。此时**不要**基于不足窗口硬算或猜数，改用更长的周期或更短的指标参数；如果换不动，就在回答里说明这一项为什么没法给出。

### 单一事实来源（重要）

- 每个响应都带 `grounding`（最后一根已收盘 bar、用了多少根、是否只用已收盘）与指标参数。**回答里引用的每个数值都必须能追到某次工具响应**；带上它的 bar 时间或参数。可核对的意思是"**引用**证据"，不是"穷举"证据——按长度预算只留与结论相关的那几条。
- 两次响应数值不一致时，说明是哪一种：通常只是中间又过了一根 K 线；若是同一根 bar 上的真冲突，**直接指出冲突**，不要编一个"调和后"的数字。
- **禁止**在没有工具输出支撑的情况下声称历史验证、"支撑阻力被反弹验证过"、或精确的百分比涨跌。有工具输出时，也要带上**具体时间与价位**。

## 置信度校准（trading_confidence）

形成方向性结论后，调用 `trading_confidence` 让 TypeSafe Jev 校准它的置信度：

| 参数 | 含义 |
|---|---|
| `symbol` | 与 `trading_chart` 一致 |
| `interval` | 与本次出图一致（15m/1h/4h/1d） |
| `direction` | `bullish` / `bearish` / `range` / `unclear` |
| `invalidation` | 失效位（价位或条件，如「跌破 63000」） |
| `thesis` | 你的结论与理由，简短即可（这段文本会发给 Jev 评分） |
| `compareTo` | **与出图时相同的那个周期**（若你用了多周期比较）。Jev 才会拿到与你相同的对比证据；不传则证据里不含共振 |

- **必须先对同一 symbol/interval 调用过 `trading_chart`**；否则返回 `ok=false, reason=evidence_unavailable`，先出图再校准。
- 出图时若用了 `compareTo` 做多周期比较，**这里要传同一个值**——否则校准依据的是另一种对比，模型与 Jev 会各说各话。
- `ok=true`：结论那一行**必须完整给出 Jev 的四项原始输出**，一个都不能省：
  **支持度**（0..4 与档位）、**置信度**（0..1 与 高/中/低）、**证据充分度**、**概率分布**（各档位的概率）。
  这些数字**不受长度预算约束**——它们是"结论可被证伪"的凭据，用户要看的就是它们；
  **不得改写、不得四舍五入、不得省略**，也不要说成"约"。
- `ok=false`（未配置 key 或服务不可用）：按你自己的判断给出置信度，并**明确声明本次未经校准**。

# 13: 把分析认定的价位补画到已打开的图上

**要构建什么：** 用户（或模型）在分析之后，能把**指定的价位**补画到**已经打开的**行情图 tab 上——
而不只是"出图时固定画每侧 N 条"。例如结论里的失效位、或模型从 `trading_levels` 里挑出的几条
关键支撑阻力/斐波那契，可以在需要时推给已渲染的图。

**Blocked by:** 12（已 done）

**Status:** ready-for-agent

## 背景

- 现状：图面价位由**出图时**的参数决定（`trading_chart` 的 `levelsPerSide` / `levelKinds`，默认每侧 3 条、
  只画支撑阻力）。出图之后再想加一条线，只能重新出图。
- 用户原话："主图上可以显示均线，后面可以再显示推荐的价格。"
- 因此缺口是**跨组件的状态传递**：分析结果（`trading_levels` 的 levels）→ 已打开的 tab（客户端）。

## 待定的设计问题

1. **入口形态**：新增工具（如 `trading_chart_levels`）？还是给 `trading_chart` 加"追加"语义？还是
   客户端 tab 自己的交互（图中加"从分析结果添加价位"）？
2. **状态归属**：已打开的 tab 由客户端持有（每回合一个 tab、旧图保留）；追加需要一条宿主→客户端的推送路径
   （现有 HTTP 端点 `/trading-agent/chart` 是"点控件→拉一份新 spec"的拉模型）。
3. **与 `ChartSpec.levels` 的关系**：追加的价位是进 spec（重画整图）还是叠一层独立的"标注"层？
   前者简单、复用现有渲染；后者能保留"机械画的"与"人/模型挑的"之间的区别。
4. **失效位是否算价位线**：结论里的失效位是一个价位，画成一条虚线很自然——但它属于"判读"而非机械候选，
   要不要在图上区分（颜色/线型/标签）？

## 验收标准（待设计定型后细化）

- [ ] 追加的价位出现在已打开的图上，且不产生新的对话消息
- [ ] 与"机械画的价位"在视觉上可区分（若按问题 3 选独立层）
- [ ] 追加失败（如 tab 已关）时明确告知，不静默
- [ ] 纯逻辑部分（价位 → 图上线的映射）有单测；渲染部分由用户实测
